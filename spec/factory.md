# sdd-factory — factory partition

> Single source of truth for the `factory` partition of `sdd-factory`: the
> command-line surface, the run lifecycle, the foreman (workspace, approvals,
> worktrees, progressive integration), publication and the cross-cutting
> policies every other partition references.
>
> **v0.1.0** — every record is `lifecycle.status: proposed`. Promotion to
> `approved` requires a human `sdd approve` + `sdd finalize`; the agent that
> authored these records cannot self-approve (SDD §7.5).

---

## 1. Context

`sdd-factory` is a multi-agent software factory built on `@mozaik-ai/core`
for the JigJoy "Software Factory" hackathon track. One command turns a
Markdown specification of unknown shape into a small TypeScript project (CLI
or HTTP API) whose tests pass, and publishes it under `hidden/<slug>/` in
this repository. No human writes product code and no human is consulted
during a run: every decision a human would have taken is either a
pre-authorised approval recorded at launch or an `ASSUMPTION` record minted
by the spec critic.

The factory applies the SDD methodology twice. Its own behaviour is governed
by the seven partition specs under `spec/` (this file plus `bus`, `trace`,
`spec-stage`, `design-stage`, `build-stage`, `assembly-stage`). The product
it builds carries its own single-partition spec generated by the spec stage
and gated by `sdd lint`, `sdd approve` + `sdd finalize` and `sdd ready`.

This partition fixes what an operator and a judge observe from outside: the
CLI contract, exit codes, the run directory, the published tree, and the
three policies (autonomy, write scope, secret redaction) that every other
partition inherits through its `default_policy_set`.

## 2. Glossary

- **Run** — one invocation of `factory run` on one source spec; identified
  by `runId` = `<slug>-<yyyymmdd-hhmmss>`.
- **Slug** — kebab-case of the source spec file basename, matching
  `^[a-z][a-z0-9-]*$`; names the product partition and the output directory.
- **Operator** — the human identity named at launch (`--operator` or
  `FACTORY_OPERATOR`); owner of every pre-authorised approval of the run.
- **Pre-authorised approval** — an `sdd approve` executed by the foreman on
  behalf of the operator, recorded in `interventions.md` as the launch step.
- **Human intervention** — any action by a person that influences a run:
  the launch itself, a fix to the factory between runs, or a nudge mid-run.
- **Product** — the TypeScript project the factory builds; lives in a
  standalone git repository under the run directory and is published as a
  plain tree.
- **Product repo** — `<runDir>/product/`, a git repository with branch
  `integration` into which approved task branches are merged.
- **Published tree** — `hidden/<slug>/` in this repository after a
  successful run.
- **Run directory** — `.factory/runs/<runId>/`, holding `run.json`, the
  product repo, worktrees, handoffs and trace.
- **Foreman** — the deterministic participant that owns workspace
  bootstrap, approval execution, worktree provisioning, verification runs
  and progressive integration.
- **Lane** — the per-task sequence test-writer → verifier → implementer →
  verifier → reviewer, executed in a git worktree.
- **Stage** — one of `spec`, `design`, `build`, `assembly`, `publish`.
- **Terminal report** — the stderr block printed when a run fails: stage,
  reason, evidence paths.

schema:
  binary: factory
  subcommands:
    - name: run
      positional:
        - name: spec
          type: path
          required: true
      flags:
        - name: --operator
          values: "<identity>"
          default: "$FACTORY_OPERATOR"
        - name: --no-push
          values: "<flag, no value>"
        - name: --out
          values: "<directory>"
          default: "hidden/<slug>"
        - name: --max-parallel-lanes
          values: "<integer 1..8>"
          default: 4
    - name: nudge
      positional:
        - name: runId
          type: string
          required: true
      flags:
        - name: --note
          values: "<text>"
          required: true
preconditions:
  - cwd is the root of a git repository (the team repository)
  - the .factory/ directory is writable
postconditions:
  - run exits only after run.published or run.failed (factory:CTR-002)

## 19. Out of scope

- Brownfield products: the factory always starts from an empty product repo.
- Resuming or replaying a failed run; the operator fixes the factory and launches again.
- Mozaik Cloud (`MOZAIK_API_KEY`) beyond passing the variable through; no behaviour depends on it.
- Windows; the factory targets macOS and Linux shells.
- Any human-facing UI beyond the CLI and the files in factory:SUR-002 and trace:SUR-001.
