## Spec conformance

- **url-shortener-api:INV-001** (state lives only in memory) — realised. `openStore()` (`src/links/index.ts:30`)
  returns a freshly constructed `{ byCode: new Map(), byUrl: new Map() }`, so no state is reachable from a
  later open; the Link, its `hits` and its `createdAt` are plain object properties of the stored record
  (`src/links/index.ts:64`, `src/links/index.ts:79`) and nothing in the module touches `node:fs` or any
  client. Tests `tests/links/links-store.test.ts:9`, `:20`, `:26`, `:39` assert the empty-after-open state,
  the deleted-then-opened case and that a previously submitted URL is new again after a restart. Flip test:
  a persistent or module-singleton store makes all four fail; they are not vacuous.
- **url-shortener-api:INV-002** (6 alphanumeric characters, unique among existing Links) — realised.
  `CODE_ALPHABET` is exactly `a-zA-Z0-9` (62 characters) and `CODE_LENGTH` is 6 (`src/links/index.ts:27-28`);
  `createCode()` draws six unbiased characters from it (`src/links/index.ts:46-52`, `randomInt`),
  matching ASM-002's uniform random selection; `createLink` retries while the drawn code is present in
  `byCode` before inserting (`src/links/index.ts:60-63`), so a collision can never overwrite an existing Link,
  and the URL index stores the code of the single surviving record. Tests `tests/links/links-store.test.ts:51`
  (5 Links), `:60` (first Link), `:65` (200 Links back to back, distinct and each resolving to its own URL)
  and `:78` (50 direct `createCode()` calls) assert the pattern and pairwise distinctness. Flip test: a
  5- or 7-character code, a non-alphanumeric character, or an overwriting collision fails at least one of them.
- **url-shortener-api:CON-002** (no durable storage) — realised. The module imports only `node:crypto`
  (`src/links/index.ts:1`) and holds state in two `Map`s; there is no file handle, no serialisation, no
  cleanup hook and therefore no handle left open, no promise boundary and no write path at all — so no
  unhandled rejection, exit code or status can go wrong on a storage path. Test
  `tests/links/links-store.test.ts:87` snapshots the working directory, creates two Links, deletes one,
  confirms the survivor still resolves, and asserts the listing is unchanged — covering both CON-002 boundary
  classes (`link created`, `link deleted`) and its named failure scenario (a state file appears).
- **No behaviour beyond the spec** — the diff adds no endpoint, flag, env var, file format or exported name
  that the records or the M-02 interface do not name. `isValidOriginalUrl`, `createCode`, `recordHit`,
  `deleteLink` and `toStats` are interface members of M-02; their presence and their observable meaning
  (`toStats` rendering `createdAt` via `Date#toISOString`) are what `design/tech.md` prescribes, and the
  behaviour they implement (exact duplicate equality, deletion clearing both indexes, case-sensitive exact
  code lookup, `http`/`https`-only original URLs) matches ASM-003, ASM-004, ASM-007 and BEH-003's input
  classes for the parts of the record set that reach this module.
- **Local semantic risk** — none on the contract path. All four operations are synchronous `Map` operations
  with no I/O, no timers and no open handles; the only loop is the collision retry, which is bounded in
  expectation and cannot spin without consuming the 62^6 space. `recordHit` and `createLink` return the
  stored record, so no caller-visible state can diverge from `byCode`.
