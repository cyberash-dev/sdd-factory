## Verdict rationale

The tests pass the flip test for all thirteen IDs: inverting BEH-018's 400/invalid_json, BEH-019's 404-vs-405 split, BEH-021's 4123/3000/ephemeral set, CTR-007's per-code statuses, INV-002's content-type-with-body rule, POL-002's survive-and-continue rule, or any of the toolchain assertions would fail the cited test rather than pass it. Mechanics are settled by `verifier.json` (`testsUnchanged: true`, `writeSetOk: true`, `covers.missing: []`, 193/193 green). Behaviour is confined to the records and the M-08 interface.

choices:

1. Non-object-but-valid JSON (array, `null`, string, number) is answered `400 invalid_json` at `src/index.ts:120-131`. BEH-018's `when` speaks of "a body that is not valid JSON", yet its `test_obligation.boundary_classes` names "JSON array instead of object" under the invalid_json predicate and the M-08 section gives the module the "JSON-object rule of DD-06". I read the boundary class plus DD-06 as deciding the HTTP-level outcome, so this is not a spec gap and not over-reach; the handler-level `invalid_room`/`invalid_booking` tests in other files call handlers directly and are unaffected.
2. `resolvePort` uses `Number.parseInt(raw, 10)` (`:184-189`), which is lenient about trailing characters (`"4123ms"` -> 4123). No record or the M-08 interface states behaviour for a non-decimal `PORT`, and CTR-007 only describes a "numerical value", so I did not raise it even as advisory: it endangers no clause.
3. The `onRejected` arm writes a bare 500 with no body (`:197-201`). CTR-007 catalogues no code for an internal fault and INV-002 says the only bodyless response is 204, but the M-08 section expressly places "the containment of unexpected exceptions of DD-12" in this module, and POL-002 only forbids crashing on invalid client input, which is fully served by the `failure(...)` paths. I treated the DD-12 containment as sanctioned rather than as a spec contradiction worth routing to `contract`, because no record asserts anything about an unexpected-exception response and no named input class reaches the branch.
4. CON-003, CON-005 and NFR-001 have predicates that are ultimately environmental (`npm run build`/`npm test` exit codes, an offline run). Their in-band tests assert the acceptance script wiring byte-for-byte and exercise the product over loopback, and NFR-001's own `verification_obligation` puts the real proof in a CI job log, while the verifier's `tsc --noEmit` and `vitest run` exits are 0. I accepted these as covered rather than demanding an in-band `npm test` invocation, which would be recursive and beyond the record's expressible obligation.
5. Fixed-port tests bind 3000 and 4123 (`tests/server/server.test.ts:117`, `:132`). That is directly what BEH-021's `then` requires, and all four PORT tests passed in the green run; I did not treat it as nondeterminism because `concurrency_model.idempotency` is not claimed for BEH-021 and no second test file binds a fixed port.
