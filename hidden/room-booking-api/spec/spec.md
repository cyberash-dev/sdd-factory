# room-booking-api product specification

> Generated by sdd-factory. Version 0.1.0; every record is `proposed` until the pre-authorised approval.

## 1. Context

`roomy` is a small HTTP API, written in TypeScript, that manages meeting rooms and their bookings. All state is held in memory and is lost when the process stops (source L1-L3). The only consumer surface is the HTTP API described in section 5; there is no other interface, no persistence and no authentication.

---

## 2. Glossary

- **room** — the entity `{ "id": "<id>", "name": "<string>", "capacity": <integer> }`; its `id` is assigned by the server as `r1`, `r2`, ... in creation order.
- **booking** — the entity `{ "id": "<id>", "roomId": "<room id>", "title": "<string>", "start": "<time>", "end": "<time>", "attendees": <integer> }`; its `id` is assigned by the server as `b1`, `b2`, ... in creation order, across all rooms.
- **room id** — the server-assigned identifier of a room (`r1`, `r2`, ...).
- **booking id** — the server-assigned identifier of a booking (`b1`, `b2`, ...).
- **time** — an ISO-8601 string in UTC with a `Z` suffix and minute precision, for example `2026-11-02T09:30:00Z`.
- **booking interval** — the half-open interval `[start, end)` of a booking; a booking ending at 10:00 and another starting at 10:00 do not overlap.
- **capacity** — the maximum number of attendees a room holds.
- **conflict** — a booking of the same room whose booking interval overlaps the requested interval.
- **earliest-starting conflicting booking** — among all conflicts, the one whose `start` is smallest; on equal `start` the one whose booking id is smallest.
- **availability window** — the half-open interval `[start, end)` passed to `GET /availability`.
- **error code** — the stable snake_case value of the `error` field of an error response.
