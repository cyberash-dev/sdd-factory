# room-booking-api product specification

> Generated by sdd-factory. Version 0.1.0; every record is `proposed` until the pre-authorised approval.

---

## 1. Context

`roomy` is a small HTTP API that manages meeting rooms and their bookings. A room is created once, with a name and a capacity, and is never updated or deleted. A booking reserves one room over one interval for a titled group of a given size. Bookings are created against a room and deleted individually; deleting a booking frees its interval for new bookings. All state lives in the memory of the running process: it is lost when the process stops, and every response is decided from that in-memory state. Every error is reported as a JSON object carrying a stable snake_case error code, so that clients branch on codes and never on prose.

---

## 2. Glossary

- **roomy** — the product: an HTTP API over meeting rooms and their bookings.
- **room** — a bookable meeting room, described by `id`, `name` and `capacity`.
- **booking** — the reservation of one room over one interval, described by `id`, `roomId`, `title`, `start`, `end` and `attendees`.
- **id** — the server-assigned identifier of a room (`r1`, `r2`, ...) or of a booking (`b1`, `b2`, ...), assigned in creation order.
- **name** — the room label, a non-empty string of at most 40 characters, unique across rooms compared case-insensitively.
- **capacity** — the largest number of attendees a room can seat, an integer in the range 1..100.
- **title** — the label of a booking, a non-empty string of at most 80 characters.
- **attendees** — the number of people a booking is made for, an integer of at least 1 when a booking is created.
- **time** — an ISO-8601 timestamp string in UTC with a `Z` suffix, on a whole minute, for example `2026-11-02T09:30:00Z`; the spellings `2026-11-02T09:30Z` and `2026-11-02T09:30:00.000Z` name the same instant and are accepted, and a time is kept and reported exactly as the request spelled it.
- **interval** — the period a booking occupies, from its `start` inclusive to its `end` exclusive, that is the half-open interval `[start, end)`.
- **overlap** — two intervals overlap when they share at least one instant; intervals that only touch at an endpoint do not overlap.
- **error code** — the stable snake_case string carried in the `error` field of an error response.

## 19. Out of scope

- Persistence of rooms and bookings: state lives only in the running process and is lost when it stops (L3, L68).
- Authentication and authorisation of clients (L68).
- Recurring bookings: every booking is a single interval (L68).
- Time zones other than UTC: every time is a UTC `Z` string (L68).
- Updating a room and deleting a room (L68).
