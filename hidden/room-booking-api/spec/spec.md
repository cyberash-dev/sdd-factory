> Generated by sdd-factory. Version 0.1.0; every record is `proposed` until the pre-authorised approval.

## 1. Context

`roomy` is a small HTTP API written in TypeScript that manages meeting rooms and their bookings. All state lives in memory and disappears when the process stops. Clients create rooms, create bookings inside a room, list rooms and bookings, delete bookings and query which rooms are free for a requested interval. Every response body is JSON; every failure carries a stable snake_case error code.

---

## 2. Glossary

- **room** — an entity `{ "id", "name", "capacity" }`; `capacity` is the maximum number of attendees it can host.
- **booking** — an entity `{ "id", "roomId", "title", "start", "end", "attendees" }` attached to exactly one room.
- **room name** — the human label of a room, non-empty, at most 40 characters, unique across rooms ignoring case.
- **booking title** — the human label of a booking, non-empty, at most 80 characters.
- **time** — an ISO-8601 string in UTC with a `Z` suffix and minute precision, for example `2026-11-02T09:30:00Z`.
- **interval** — the half-open time range `[start, end)` of a booking.
- **overlap** — two intervals overlap when they share at least one instant; an interval ending at 10:00 and one starting at 10:00 do not overlap.
- **attendees** — the integer number of people a booking serves.
- **available room** — a room whose capacity is at least the requested attendee count and that has no booking overlapping the requested interval.
- **error code** — the stable snake_case value of the `error` field of an error response.

## 19. Out of scope

- Persistence of any kind; state is lost when the process stops.
- Authentication and authorization.
- Recurring bookings.
- Time zones other than UTC.
- Updating or deleting rooms.
- Cross-room or multi-room bookings.
- Pagination of room or booking listings.
- TLS termination and deployment concerns.
