## Findings

RV-001 — advisory, target `none`, spec_ids `["todo-cli:CTR-002"]`.

`todo-cli:CTR-002.error_taxonomy` names three branches: `exit 0 E_SUCCESS`, `exit 2 E_USAGE - usage line on stderr starting with usage:` (the "unknown flag" boundary class) and `exit 1 E_STORAGE - error line on stderr starting with error: cannot read`. The frozen file asserts only the `E_SUCCESS` behaviour (`:29`, `:54`, `:87`, `:93`, `:99`, `:105`) and the `E_STORAGE` behaviour (`:116`, `:126`). Evidence: `tests/read-commands/read-commands.test.ts:116` — `it.each([false, true])("reports E_STORAGE with exit 1 ...")`.

The `E_USAGE` branch is not reachable from this module's surface: M-04's contract is `runList(path: string, all: boolean)` / `runHelp()`, i.e. argument vectors are already parsed by the caller, and rule §M-04 states `runList` only maps storage failures. The same clause is owned by `todo-cli:BEH-013` and `todo-cli:ASM-008` in the argument-parsing task, whose write set covers the CLI dispatcher. This note is therefore recorded for trace only: it is not a coverage failure of the predicate `test_obligation.predicate` of CTR-002 ("list prints one line per shown task, ascending id, nothing when empty"), which is asserted, and no rework is requested from the test-writer or the implementer.
