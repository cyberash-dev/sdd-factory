## Findings

### RV-001 — advisory, target `none` — the CTR-007 error-line clause is not asserted in this task's tests

- **spec_ids:** `todo-cli:CTR-007`
- **evidence:** `todo-cli:CTR-007 schema.error_message: "error: cannot read <path>, where <path> is the resolved path printed verbatim"`; `tests/store/store.test.ts:76` asserts only the resolution clause (default `./todo.json`, verbatim `TODO_FILE`), and `src/store/index.ts:22-25` returns the path with no error-line rendering, so nothing in the M-02 write-set can assert the error line.
- **detail:** `CTR-007.test_obligation.predicate` names two halves — the resolved path and "the error line names that path". The second half is a stderr obligation of `todo-cli:SUR-001` rendered by the command layer, and M-02's interface (per the `design/tech.md` M-02 section) deliberately exposes no message formatter. The obligation is therefore carried by the command-layer task that owns stderr; recorded here so trace shows the split rather than a silent gap. No change requested in this lane.

### RV-002 — advisory, target `contract` — no record states how `nextId` relates to the stored ids

- **spec_ids:** `todo-cli:INV-002`, `todo-cli:CTR-006`
- **evidence:** `todo-cli:INV-002 statement: "an id that has ever been assigned to a task in a storage file is never assigned to another task in that file"`; `src/store/index.ts:50-62` accepts a file such as `{"nextId":1,"tasks":[{"id":1,...}]}` as the contract shape (CTR-006 only requires `nextId` to be an integer ≥ 1), so the read layer offers no way to tell that the file's `nextId` is already behind its ids.
- **detail:** For every file the store itself writes this cannot arise, and `CTR-006` is satisfied as written. It becomes visible only for a hand-edited or foreign-written file that is still in the contract shape; whether such a file must be rejected as `E_CANNOT_READ`, or whether the add path must allocate `max(nextId, maxId + 1)`, is not stated by any record. This is a record gap, not a diff defect, and the id allocation itself lives in a later task; logged for the spec-critic rather than as a rework request.
