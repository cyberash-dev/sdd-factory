Boundary classes of the record — whole `12`, one fractional digit `12.5`, two fractional digits `12.50` — are all handled. Negative cases: `ledger add abc coffee` resolves to `null` at this layer (exit 2 `E_USAGE` is emitted by the CLI layer, `CTR-001.error_taxonomy`, outside `src/domain/**`); "storing 12.5 as the float" is impossible because the parser returns an integer cents value. Realised.
- **INV-003** (`title: dates are stored as YYYY-MM-DD calendar days in UTC`; `predicate: "every stored date is a valid calendar day rendered as YYYY-MM-DD and the default is the current UTC day"`). `src/domain/index.ts:63-79` (`isCalendarDate`) matches `^(\d{4})-(\d{2})-(\d{2})$` only, then round-trips through `Date.UTC` with `setUTCFullYear` (correctly handling the 0-99 year remap) and compares year, month and day, so `2026-02-30`, `2026-02-29` (non-leap 2026), `2026-13-01`, `2026-00-xx` and `xx-00-xx` are all `false`, while `2028-02-29` is `true`. `src/domain/index.ts:85-87` (`utcDayOf`) returns `now.toISOString().slice(0,10)` — the UTC calendar day of the caller-supplied instant, no ambient clock read (DD-05 respected, `time_source: clock` is satisfied by the caller passing the `Date`). ### RV-001 — advisory, target `test-writer`

- **spec_ids:** `expense-ledger-cli:INV-003`
- **evidence:** `expense-ledger-cli:INV-003.test_obligation.failure_scenarios: "a local-zone day is stored by default"`; `tests/domain/domain.test.ts:52-56` asserts `utcDayOf` on concrete UTC instants (`2026-10-31T00:00:00.000Z`, `2026-11-01T00:00:00.000Z`, `2026-10-31T23:59:59.999Z`, `2028-02-29T12:00:00.000Z`) but pins no process time zone, so a `getFullYear`/`getMonth`/`getDate` (local) implementation would still satisfy those assertions when the suite runs under `TZ=UTC`, and would only fail under, say, `Asia/Tokyo`.
- **Why not blocking:** the record is realised by the implementation itself — `utcDayOf` reads `toISOString()`, which is UTC by construction — so the invariant is provably met and this does not endanger a record clause in this diff. The note is that the guard against a future local-time refactor is weaker than the record's failure scenario asks for. Suggestion for a later pass (not required for approval): pin `TZ` for the calendar-day block, e.g. `process.env.TZ = "Asia/Tokyo"` before the suite, or assert through an offset-bearing instant whose local and UTC days differ in the runner's zone.
- **Routing note:** advisory only; with `advisory_only` the report-level `target` is `none` and no lane is restarted.
