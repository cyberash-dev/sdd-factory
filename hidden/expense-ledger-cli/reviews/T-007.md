## Verdict rationale

Every one of the ten IDs has a `// @covers` marker in the task's frozen test files and at least one non-vacuous asserting test (each fails if the record's expectation is inverted). The implementation realises the record predicates and the error taxonomy from `CTR-008`: usage failures exit 2 with a single `usage:` stderr line and empty stdout (`src/index.ts:34-37`), error failures exit 1 with a single `error:` line (`src/index.ts:43-46`), and stdout is written only after success is known, so INV-007 holds. No flag, endpoint or output format beyond what the records name appears in `src/index.ts` or `src/cli.ts`, and neither module departs from the M-07 interface or the stated binary shape in `design/tech.md`. No local semantic risk on a boundary path: ledger handles are synchronous `readFileSync`/`writeFileSync` calls that never stay open, `readLedger` converts every fs and parse failure into `E_UNREADABLE_STORE` instead of throwing, and no promise escapes `main`. `testsUnchanged: true` and `writeSetOk: true` in `verifier.json` settle the mechanics.

choices:
- The help path prints `USAGE_TEXT` (whose first line begins with `usage:`) on stdout with exit 0. CTR-006 declares the usage text informational and stable only in that exit 0 and the command names appear, and BEH-015 requires stdout, so writing it on stdout is conformance, not drift; not a finding.
- Test CON-004 checks network absence by static import scanning of `dist/**` plus every command succeeding, rather than instrumenting sockets. The record's predicate is "no command opens a network connection"; with a dependency-free, fs-only implementation the static scan is a real assertion (a network import or `fetch(` would fail it) and I do not demand more than the record obliges.
- CON-002's version assertion reads the ambient runtime; it is not vacuous because the same test also runs the built CLI and the assertion fails on a pre-22 runtime, which is the failure the record names.
- The nested `npm test -- tests/cli/main.test.ts` in CON-003 is a deliberate recursion guard for the self-referential suite; it still exercises the vitest wiring the record requires, so no test-writer finding.
