## Findings

**RV-001 — advisory, implementer.** ASM-014 resolves BEH-028's interaction with INV-010: an over-limit head that does not fit remains queued and prevents service behind it. Concrete input: a customer holds five tickets in another tier, the first entry requests two tickets in a sold-out three-ticket tier, the next entry requests one, and cancellation frees only one ticket. The required outcome is that both entries remain, with no new order. `serveTier` instead removes the first for exceeding six and creates an order for the second. This observation is advisory under the attempt-2 rule because the unavailable prior report and prior implementation do not establish it as a new regression.

**RV-002 — advisory, test-writer.** For `ONCE` with maxUses 1, the record requires a second checkout while the first is held to return 422 E_DISCOUNT_UNUSABLE, followed by a successful checkout after expiry. The marked test never makes that second checkout, and no test asserts either HTTP status. An implementation that permits the second checkout could pass this test. The store interface explicitly assigns precondition checks to the caller, so this cannot be repaired by demanding that `holdOrder` independently emit the HTTP error. This coverage observation is advisory under the attempt-2 rule.

**RV-003 — advisory, test-writer.** With HOLD_SECONDS unset the product must use 600 seconds, and with it set to 2 it must use 2 seconds. The test supplies those numbers directly to `createStore`; an environment reader that always supplies 600 could leave these tests green even when HOLD_SECONDS is 2. The design deliberately passes `holdSeconds` as an option, so environment loading belongs outside this store interface. This coverage observation is advisory under the attempt-2 rule.
