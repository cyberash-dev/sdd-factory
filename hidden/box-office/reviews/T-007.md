## Findings

**RV-001 — advisory, implementer.** POST `/events` with body `[]` and no Authorization must answer 401 E_UNAUTHENTICATED: the body is valid JSON and token precedes input validation. The implementation instead answers 400 E_INVALID_INPUT. With a customer token it likewise answers 400 rather than 403. The object check is at `src/app/index.ts:154-156`, before auth at `:159-168`.

**RV-002 — advisory, implementer.** POST `/events/x/cancel` with body `{bad` is a served method and route. BEH-031 requires 400 E_MALFORMED_JSON before authentication, but the route is marked `readsBody: false` and the body is discarded; without a token it returns 401. M-08 describes syntax validation on body-reading routes, whereas BEH-031 states the broader served-route predicate.

**RV-003 — advisory, implementer.** POST `/events` without a token and a valid JSON object containing an ignored string field longer than 1,048,576 bytes must reach the token check and answer 401. The body-size cap instead yields 400 E_MALFORMED_JSON even though the body is valid JSON. The approved records do not specify a body-size limit.

**RV-004 — advisory, test-writer.** The CST-002 test does not make outbound networking unavailable or detect outbound calls. For example, an implementation that makes a successful outbound call during registration and then returns the same 201 would still pass; inverting the no-outbound expectation therefore does not fail this test. The verifier's green result does not establish this predicate.

**RV-005 — advisory, contract.** CTR-014 explicitly requires 400 E_INVALID_TIER for a foreign tier and the implementation and frozen test follow that text. Approved ASM-016 instead directs that CTR-014 be changed to 404 E_NOT_FOUND. For an existing event and a tier from another event, these two readings require different answers. The inlined approved contract is used for the coverage assessment; the contradictory assumption is recorded for resolution.
